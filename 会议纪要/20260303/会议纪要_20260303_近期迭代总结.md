## 1. 已提交到Git的主要变更

### 1.1 数据层值语义归一（Step05B）

对应提交：
- `73adc39` feat: add value normalization stage with data-layer semantics
- `bd11cd1` feat: use alias-only strict dict and closed-set rate true values

主要内容：
- 新增 Step05B 值归一智能体（`ValueResolveAgent`），在意图澄清后、SQL生成前做条件值落地。
- 映射层新增 `field_value_semantics`（数据层）配置支持，支持：
  - `closed_set`
  - `labels`
  - `aliases`
  - `rate_true_values`
  - `confidence_threshold`
  - `unknown_policy`
- 对区划类字段（如 `AREACODE`）采用更严格的 alias 直映策略，减少模型随意归一。
- 后台映射管理页支持“字段值语义(JSON，数据层)”可视化编辑与保存。

效果：
- 解决“用户说线上/未上云，库中存1/是”的落值问题。
- 降低布尔字段穷举猜测导致的SQL偏差。

### 1.2 率计算口径增强（包含正负向语义）

对应提交：
- `f2034a0` feat: improve rate polarity handling and update pipeline docs

主要内容：
- 率计算支持基于数据层语义闭集提取真值集合（`rate_true_values`优先）。
- 对“负向率”问题（如“不共享率/未按时更新率”）增加极性识别，必要时使用闭集补集计算分子。

效果：
- 减少“默认按‘是’统计”造成的口径错误。
- “共享率/不共享率”能按语义区分计算。

### 1.3 问题拆解与值归一提示词可配置化

对应提交：
- `36633db` feat: make split/value-resolve prompts configurable and improve split planning

主要内容：
- 将问题拆解、值归一相关提示词接入“提示词配置”模块，支持后台维护。
- 问题拆解策略由纯规则向“模型规划+校验”方向增强，减少中文误切。

效果：
- 调整拆解行为不再必须改代码。
- 便于快速调优“单SQL优先/多任务拆分”判定。

### 1.4 JOIN能力升级（INNER + LEFT）并引入模型判定

对应提交：
- `fd85e16` feat: support inner/left join planning and SQL generation
- `f5319c7` feat: llm-driven join type with configurable prompts and group_count target fix

主要内容：
- 查询规划与SQL生成支持 `INNER JOIN` + `LEFT JOIN`。
- JOIN类型由LLM判定（并提供回退规则），提示词可配置：
  - `join_type_system`
  - `join_type_user`
- 增加JOIN策略日志，便于定位“为什么是LEFT/INNER”。
- 对 `group_count` 场景做目标修正（避免统计对象错位）。

效果：
- 支持“主表全保留”类问法（如“项目及其关联系统数”）的LEFT JOIN需求。
- JOIN策略更可解释、更易调优。
