# 会议纪要：智能问数系统迭代（本体别名、关联配置、知识配置、日志与修复）

- 日期：2026-02-26
- 参与：业务方、开发（AI 协作）
- 主题：提升自然语言问数在俗语/行业语下的可用性，完善本体管理能力与可观测性

---

## 1. 背景与核心问题

系统流程为：用户提问 -> 模型理解本体 -> 抽取实体/属性/条件/计算方式 -> 生成 SQL -> 执行并返回答案。

本轮重点问题：

1. 俗语/口径词导致条件值不标准
- 示例：`省内` 应映射为 `江苏省`，否则 SQL 条件错误。

2. 垂直领域概念需要知识解释
- 示例：`业务系统`、`应编未编` 等需要长文本口径辅助理解。

3. 多实体查询关联键不能靠猜
- 示例：`计算机2301班有多少学生` 需要稳定、可配置的表间关联关系。

4. 后台可用性与可观测性不足
- 本体编辑/属性编辑交互缺陷
- 页面展示宽度与可读性问题
- 日志缺少关键信息（SQL、值别名归一化、JOIN 来源）

## 3. 关键验证结论

### 3.1 班级学生数查询

问题：`计算机2301班有多少学生`

结论：
- 在配置了 `Student.class_id -> Class.class_id` 后可正确回答。
- 本体文件中对应关系已存在并带字段：
  - `from: Student`
  - `to: Class`
  - `from_field: class_id`
  - `to_field: class_id`

### 3.2 是否确实使用了“关联配置”

结论：
- 当前代码逻辑为“先配置、后兜底”，不是纯猜测。
- 新增日志可直接观察 JOIN 来源，便于线上核对。

## 4. 问题与修复记录（页面乱码）

出现问题：
- 管理页多个模块出现乱码/问号（如 `瀹炰綋...`、`????`）。

原因：
- 在 Windows 环境下进行批量文本处理时，发生了 UTF-8 与本地代码页混用，导致部分中文被错误转码/替换。

处理：
- 已对本体管理、数据表管理、映射管理、知识配置、用户权限的关键文案进行修复。
- 对 `admin.js` 做了语法校验，保证可加载。

备注：
- 历史旧文件中仍可能存在少量历史编码痕迹，后续按页面发现逐步清理。

## 7. 近期改动补充（2026-02-27 ~ 2026-02-28）

### 7.1 本体与映射

- 本体导入逻辑调整为“本体驱动 + 表映射适配”：支持存在“仅本体、无对应物理表字段”的场景。
- 导入格式统一为 xksx Excel：
  - `Sheet1`：本体名称、属性中文名、属性英文名
  - `Sheet2`：本体关系
- 后台增加导入入口，支持后续按同格式重复导入覆盖更新。

### 7.2 执行链路与数据源

- 计算执行链路由读取测试 Excel 为主，切换为优先走 MySQL SQL 执行。
- 后台新增数据库连接配置入口（数据源连接参数可维护）。
- 生成并补充了 MySQL 建表与测试数据脚本（含 `rowguid` 的表以 `rowguid` 为主键）。

### 7.3 语义与 SQL 生成修正

- 新增“全局同义词（键值型）”配置与生效日志（例如：`全省/省内 -> 江苏省`）。
- 条件生成适配 MySQL：`contains` 转为 `LIKE`，并对区划条件增加“contains -> =”收敛策略。
- 修复多实体场景关联配置可视化问题：关系编辑入口恢复，可维护 JOIN 关联字段。
- 修复 `group_count` 场景未正确聚合问题：在存在数值指标时通过兼容映射按指标聚合（如 `SUM`）。
- 优化 `LIMIT` 规则：仅在明确 TopN/排名语义时保留限制条数，避免默认 `LIMIT 10` 误触发。

### 7.4 知识与提示词配置

- 增加“指标 SQL 规则”能力：命中规则后优先走预定义 SQL，并支持叠加解析出的筛选/分组/排序参数。
- 增加提示词配置模块：可在后台维护各模型调用节点的提示词模板。
- 提示词配置页新增运行时模型参数：
  - `base_url`
  - `model`
  - `api_key`
  - 未配置时回退到 `config.py` 默认值。

### 7.5 可观测性增强

- 每次问答输出目录新增 `llm_traces.json`，记录模型调用输入/输出轨迹。
- 意图澄清步骤增加模型原始 JSON 返回日志，便于排查 `calc_type / calc_params` 偏差来源。
